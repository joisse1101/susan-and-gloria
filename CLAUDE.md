# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server (also serves the DuckDuckGo proxy, see below)
- `npm run build` — `tsc -b && vite build` (type-check then bundle to `dist/`)
- `npm run lint` — ESLint
- `npm run preview` — serve the built bundle

- `npm test` — Vitest (`vitest run`); covers the wander grid, pathfinding, desk slots, chair reach, jam detection and give-up decisions (`interaction/npc/*.test.ts`) and the player session. Pure logic only: nothing that needs Phaser's runtime is tested.

## Architecture

A client-only React 19 + TypeScript + Vite app (SCSS styles, `BrowserRouter` with `basename` = the Vite base, so routes are real paths like `/susan-and-gloria/office/`) deployed to GitHub Pages via `.github/workflows/deploy.yml` on push to `main`. `vite.config.ts` sets `base: '/susan-and-gloria/'` and its `spa-404-fallback` plugin copies `dist/index.html` to `dist/404.html`, which is how GitHub Pages serves deep links.

There is no backend: the LLM calls run **in the browser** against a local Ollama server.

### Agent pipeline (`src/agents/`)
- `agentGraph.ts` — LangGraph `StateGraph`: `START → orchestrator → (conditional on state.targetAgent) → susan | gloria → END`. Exports the compiled `appGraph`. Shared state includes `onToken` / `onRoute` callbacks that the UI passes in via `appGraph.invoke({...})` (see `pages/Home.tsx`) to stream tokens and learn which persona was routed to.
- `theGreatOne.ts` — the orchestrator node. It asks the LLM to reply with a single word and routes to `gloria` if the output contains "gloria", otherwise defaults to `susan`. Routing options are built from `PERSONAS[*].whyMe`.
- `agents.ts` — `createAgentNode(persona)` factory: builds messages as `GUARDRAIL` + persona system prompt + history + user input, streams the response, and calls `state.onToken`. Returns updated `messages` history (note the reducer replaces the array rather than appending).
- `personas.ts` — `GUARDRAIL` (safety rules that override personas) and `PERSONAS` (system prompt + `whyMe` per persona). Adding a persona requires updating the `createAgentNode` type union, the graph nodes/edges, and the orchestrator's fallback parsing in `theGreatOne.ts`, which hardcodes `gloria`/`susan`.
- `llm.ts` — `createLLM()` is the single place for LLM config (`ChatOpenAI` pointed at `http://localhost:11434/v1`, model `llama3.1:8b`, key `"ollama"`). Ollama must be running locally for chat to work.

### Tools (`src/tools/webSearch.ts`)
LangChain `web_search` tool that fetches `/api/duckduckgo/html/?q=...` and parses results with `DOMParser`. That path only exists via the **Vite dev-server proxy** (`server.proxy` in `vite.config.ts`) — it will not work in the deployed GitHub Pages build.

### The Office (`src/pages/TheOffice.tsx`, `src/game/office/`)
A Phaser 4 mini-game mounted at `/office` (outside `MainLayout`). React owns the page and the chat `<input>`; Phaser owns the canvas. They talk only through `OfficeGame`'s imperative API (`setTyping`, `showPlayerSpeech`, `destroy`), called via a ref; the input's focus/blur toggles `setTyping` so movement keys are disabled while typing. Susan and Gloria are animated four-direction sprites (idle + walk sheets in `public/assets/sprites/<name>/`, generated by `pixel-art/<name>-idle/build.py`) but are not yet wired to the agent graph.

- `OfficeGame.ts` — `Phaser.Game` config (600x400, arcade physics, pixel art) and the API above.
- `OfficeScene.ts` — the scene: `create()` lays the floor, places furniture/NPCs/player, `update()` handles movement. **Edit this to change the room layout** (`place(name, x, y, { solid, flat })`).
- `interaction/player/PlayerWork.ts` + `playerSprite.ts` — standing still in a work zone makes the player sit and type: `OfficeScene.updatePlayerAnim` plays `player-type-<facing>` and seats the player via `NpcSeats`: the same routed chair trip as the coworkers (below), started automatically when they stand still in a zone and cancelled by any movement key, typing or chat; none in reach means they work standing on `WorkStanding.png` (`player-standing-<facing>` anims, built from Idle's tall frame by the same `build.py`). A jammed chair makes them say a `JAM_PHRASES` line, walk back to the spot and work standing; losing the trip (blocked, too slow, no way back) makes them say a `FORGETFUL_PHRASES` line and get control back with no work. The session logic is the pure `playerSession.ts`; the work timer starts once they are seated using the chair sandwich (`SeatLayers`: `ChairSheet.png` one depth step behind, `ChairHandleSheet.png` armrests one step in front; per-facing nudge in `CHAIR_OFFSET`). The seated sheet `public/assets/sprites/player/WorkSitting.png` is **generated, not hand-edited**: run `python pixel-art/player-type/build.py` (Pillow; also writes `preview.png`). It builds from `Idle.png` (head, legs) and `Shoot.png` (arms). Tunables are constants at the top (`SIT_DROP`, `ARM_X`, `FAR_X`). Side views draw both hands in `side_upper`; the left view is built mirrored, so check both after changing hand positions.
- Susan and Gloria have the same kind of seated sheet (`public/assets/sprites/<name>/WorkSitting.png`), also **generated**: run `python pixel-art/npc-type/build.py` (writes both, plus `<name>-preview.png`). It derives from each `Idle.png` and copies the player's look: arms tucked into the torso, belly hands in front/back, a reaching near arm plus a shaded far hand in the side views. Per-character tuning (sleeve colour, `leg_row`, `arm_rows`, `hand_y`) lives in `CHARACTERS`. `CharacterSprite.type` in `playerSprite.ts` loads and animates the sheet, and `OfficeScene.updateSheetAnim` plays it while a coworker is working. If a loose chair (`furniture/Chairs.ts`) is within 5 tiles when they reach a work spot, `interaction/npc/NpcSeats.ts` has them walk to it, pull it back, slide it under them and work seated in the same `SeatLayers`; with no chair in reach they work standing, playing `<name>-stand-<facing>` from `WorkStanding.png` (same `build.py`, from Idle's tall frame).
- `interaction/Shadows.ts` � shadows are **separate images**, not baked into the character sheets (rows 30-31 of every cell are empty). `Shadow.png` (characters) and `ObjectShadow.png` (chairs, 5px flat oval) are generated by `python pixel-art/shadow/build.py`. A `Shadows` instance follows each sprite just behind it in depth; a seated character's own shadow is hidden (`hideWhen`) and `SeatLayers` draws the chair's instead. Nudge the chair shadow with `CHAIR_SHADOW_OFFSET_Y`. The characters' collision body is lifted `FEET_LIFT` px (`constants.ts`) so it ends at the soles, not the shadow rows.
- Pushables (`interaction/pushChain.ts`, pure and tested; wired in `furniture/Chairs.ts` `gate()`, called last in `OfficeScene.update`): chairs and free coworkers are pushed by *drivers*, bodies moving under their own power (the player walking or pulling, a walking coworker). Each frame the resolver decides per axis whether a chain may move; if anything in it would end in a wall, desk, world edge, the player or an immovable coworker, the whole chain stops, the driver included. A coasting chair never pushes a coworker; a chair the player pushes or pulls does; a coworker never pushes a coworker through a chair. Shift pulls the nearest loose chair or free coworker, one at a time; a pulled body trails the player and is let go of (not the player stopped) when blocked. A coworker is immovable while a bubble is up or from reaching its desk (`OfficeScene.isImmovable`). Hosts (`Wander`, `WorkInteraction`, `NpcSeats`) read one signal through `PathFollower.isBlocked`: `PUSH_STOPPED` (push refused) or `PUSH_SHOVED` (first frame displaced, or let go after a pull), set as data on the coworker; a held coworker has `PUSH_HELD` and `Wander` leaves its steering alone. **Tune the feel in `pushTuning.ts`**: chair/coworker mass, chair and shoved-coworker drag, `ROLL_MS`, chair max speed, each coworker's max speed (their walking speed is that times `COWORKER_WALK_FRACTION`), player walk speed, and pull and push speed per chair or coworker (each separate for chairs and coworkers), each commented.
- Spawning (`interaction/npc/spawn.ts` + `reachable.ts`, pure and tested): `OfficeScene.spawnAll` runs once at the end of `create()` (sprites start at 0,0) and places the player, Susan, Gloria and each chair on a random cell of the largest connected `walkGrid` region (chairs also on `clearGrid` cells), so no hardcoded start coordinates and no sealed pockets. Zones to avoid are every desk's work zone (`WorkInteraction.zoneRects`) and each plant's reach zone. Spawns keep `SPAWN_GAP_PX` between them. A body that finds no room relaxes the gap first (halved down to 0), then the zones, with a `console.warn` each; no floor at all throws. Placement is by *body* centre (`spritePosForBodyCentre`), not sprite position.
- `interaction/npc/NpcBubbles.ts` — NPC speech bubbles (notice, mutter, scrollable streamed reply); `OfficeScene` delegates its public NPC API to it.
- Work trips (`interaction/npc/WorkInteraction.ts`, `NpcSeats.ts`): a coworker (and the player, see above) claims a free desk in `WorkSlots` (a desk is a run of touching `interaction = work` tiles, built by `npc/desks.ts` from the shared `groupTiles` + `splitToMax` in `zones.ts`, at most `MAX_DESK_PX` = 32 px across: a longer run is cut from its top-left, so keep desks a multiple of 32 px or leave an untagged tile between neighbours; its zone on each open side is `WORK_RANGE_PX` = 24 px deep along the whole edge, tuned in `npc/workTuning.ts`; one holder per desk, claimed at the pick; the player holds one while working but is never blocked), walks to its zone along the A* route (`PathFollower`), is turned away with a `DESK_TAKEN_PHRASES` line if the player is in the way, then fetches a chair: a loose chair is in reach if it is within 5 tiles in a straight line and its walking route is at most 15 tiles (`chairReach.ts`, pure). They walk to it (planned on the walker grid), drag it to half a tile behind the work spot (planned on a second, "clearance" grid: `WalkGrid` with the `CHAIR_CLEARANCE_CELLS` footprint, so the 28x16 px chair fits; a chair with no clearance route is skipped) and sit. While towing, `chairJam.ts` watches how far the chair trails the walker: over `JAM_MARGIN_PX` for `JAM_TIME_MS` is a jam, the chair is left (not taken again for `JAMMED_CHAIR_COOLDOWN_MS`, wherever it is moved) and the walker says a `JAM_PHRASES` line and works standing. A coworker whose chair the player takes with Shift says a `STOLEN_PHRASES_NICE` line followed by a make-do line (one bubble) and works standing. A trip lost any other way (`giveUp.ts` decides; desk-taken comes first) makes a coworker say a `FORGETFUL_PHRASES` line, release the desk and wander. **Tune the jam and clearance values in `chairTuning.ts`.** Phrase lists live in `interaction/workPhrases.ts`.
- Debug aids (all off by default, ignored while typing in the chat): **G** tints the walk grid over every map (`WalkGridOverlay`; free cells outside the office, i.e. the bathroom, are light blue = player only, via the pure `overlayCell.ts`); **H** shows the clearance grid (office: green a chair fits, yellow only a walker; bathroom: light blue; red blocked everywhere); **C** shows chair reach (`ChairReachOverlay`: yellow marks the desk each coworker is heading for; the 5-tile range circle per work spot, green lines with the route length for chairs in reach, red with the reason for those filtered out: claimed, recently jammed, too far, no route, route too long, no drag route). In the chat box, `/gloria-work` and `/susan-work` send that coworker to a free desk now. **B** makes the player's current or next chair trip fail as if blocked, to see the give-up.
- Tile interactions (`interaction/registry.ts`): work and watering both implement `Interaction` (`update`, `cancel`, `isActive` = heading for or doing it, `isEngaged` = at its spot so a coworker can't be pushed, `pose` drives the animation). Two `InteractionRegistry`s, `coworkerInteractions` and `playerInteractions`, hold them in priority order and keep an actor in at most one; the scene asks the registry, not each interaction. Shared building blocks, all pure and tested: `trigger.ts` (`shouldStart`, `Cooldowns`, `stillBlocked`), `zones.ts` (`Rect` helpers), `npc/route.ts` (`routeToRect`, with an optional aim point), `npc/approach.ts` (`stepOntoSpot`), `npc/deskSpot.ts` (`spotAgainst`, `facingFor`), `sayThenHide.ts`, and `WorkSlots` (one holder per desk or plant).
- Watering (`interaction/WaterInteraction.ts`, generic over the actor id; one instance for coworkers, one for the player): an actor in reach of the plant (`plants.ts`: tiles with the Tiled property `interaction` = `water` merged into one `Plant`, its `solid` bounds taken from the collision bodies, reach zone = plant grown by `WATER_REACH_PX`, via the shared `growRect`) claims it in `PlantShared` (`WorkSlots`, shared `Cooldowns`), picks a side with `standSide` (the side it is on, never the wall side), routes to a spot `SPOT_GAP_PX` off the plant's solid, faces it and waters for `WATER_DURATION_MS`. The player must stand still in reach to start, and after a trip must leave reach before another. Someone finding the plant being watered says a `PRAISE_PHRASES` line once per encounter (`praise.ts`). Standing sheets are used (`<name>-stand-<facing>`), plus `WaterProps` overlays: the can (`WateringCanStanding.png`) and the stream (`WaterStream.png`, laid out by the pure `waterPropLayout.ts`, bobbing `WATER_BOB_PX`). **Tune in `waterTuning.ts`** (reach in px, so the map's tile size does not matter): reach, duration, cooldown, give-up time, stream bob. Debug: `/gloria-water` and `/susan-water` in the chat send that coworker to the plant now; **P** shows the plant and its reach zone (`plantOverlay.ts`).
- `interaction/npc/Wander.ts` — NPC random walk; `interaction/player/Chat.ts` — in-game chat input and the player's speech bubble.
- `map/loadTiledMap.ts` — the map-agnostic loader: a `MapSpec` (files, `offset`, `topLayers`, optional `limitsWorldToLayer` that limits the physics world) in, `{ size, bounds, walkBehind }` out. It builds each tile layer, per-tile opaque collision rects and the walk-behind pieces in the map's own coordinates and translates by the offset only where it hands things to the scene. `map/loadOfficeMap.ts` is a thin wrapper holding the office's constants (keys, `Room Boundary Bottom`, `Floor`). `?dumpMap` (dev server only; `=baseline` for the reference) saves what the loader produced to `.map-dumps/office-*.json` (git-ignored), to prove a loader refactor leaves the office unchanged.
- Walking behind objects (`map/walkBehind.ts`, pure and tested; wired in `loadTiledMap.ts`, so every map gets it, and `OfficeScene.fadeWalkBehind`): automatic, no authoring in Tiled. A solid object is a vertical run of touching 8 px cells (`CELL`) where any collider layer draws an opaque pixel, outside `TOP_LAYERS`. Its top strip, `min(WALK_BEHIND_STRIP_PX, floor(2/3 x height))` rounded down to whole cells, has no collision body, so characters walk into it; the rest blocks as before. Because the walk grid is built from the bodies, routing, clearance and chair reach follow. Tiles of an object (and decor on non-collider layers inside it, e.g. `Wall Details`) are hidden in their layer and redrawn as images at depth = base line + `FEET_LIFT * SPRITE_SCALE`, so a character is drawn behind while its feet are above the base line and in front below it. Each tile fades on its own (`WALK_BEHIND_ALPHA`, `WALK_BEHIND_FADE_MS`) only where a character's feet width and sprite height overlap it; actors watering are skipped. Objects whose run reaches map y 0 (top wall, side walls, anything stacked on them such as the plant) are not walk-behind: fully blocking, always under characters. Layers in `TOP_LAYERS` (`Room Boundary Bottom`) stay over everyone and fade the same way; a configured name missing from `map.json` logs a warning. Tune in `constants.ts`.
- The bathroom (`map/loadBathroomMap.ts`): a second Sprite Fusion map (`public/assets/map/bathroom/`) placed side by side with the office: `joins.ts` (pure, tested) finds each map's `isJoin` tile from the Tiled JSON and `placeBeside` puts the bathroom's join in the cell directly left of the office's, on the same row, so the doorways line up and no cell is drawn by both (a map with no join throws an error naming it). It is built by the same `loadTiledMap` with its own `MapSpec`. Only the player may go in: the physics world and walk grid stay the office floor, so coworkers and chairs never path or spawn there; `player.body.setBoundsRectangle` widens the player's bounds (the camera uses the same union), and `Chairs.keepOutOfPlayerArea` (the `keepOut` argument of `resolvePush`) stops pushed or pulled chairs and coworkers at the office's left edge (it assumes the bathroom is left of the office). The G/H overlays give the bathroom its own grids (`gridOverRegion`) drawn at its offset.
- `constants.ts` — canvas size, sprite scale, depth layers, feet-collision height.
- `atlases/officeAtlas.ts` — frame rectangles for characters/desks in `PixelOfficeAssets.png`.
- `atlases/interiorAtlas.ts` — frame rectangles for floors/rugs/furniture in `InteriorTilesLITE.png` (labelled map: `docs/interior-atlas-preview.png`).
- Spritesheets are in `public/assets/office/` (credits in `CREDITS.md`); frames are cut from the sheets at runtime. Rendering uses y-based depth sorting (`sortByBottom`) so characters walk behind/in front of objects.

### Character viewer (`src/pages/CharacterViewer.tsx`, `src/dev/characters/`)
Dev-only page at `/susan-and-gloria/dev/characters` (registered in `App.tsx` only when `import.meta.env.DEV`, so it is not in the production bundle; not linked anywhere). It composites a layered character on canvases from the build's output in `public/assets/characters/` (`layout.json`, `layer-order.json`, `presets.json` and `variants.json`, hand-maintained now that the sheets are hand-edited; the generator is gone), so a new variant, animation or facing shows up after editing the JSON and pressing the **Reload data** button, no page change. Pure logic is tested: `cells.ts` (which cells to stack, `DIM_ALPHA` for the highlighted layer) and `state.ts` (reducer and key map); `draw.ts` is the canvas and sheet cache, `clock.ts` one shared animation clock. Hovering a layer title or tile, or selecting its row by keyboard, dims the other layers. Keys: Up/Down layer row, Left/Right variant, **H** hide, **E** expression, **1-4** animation, **[ ]** facing, **Space** play/pause, **, .** step, **- +** slower/faster, **G** cell overlay, **O** layer-order list, **S** shadow, **B** background, **Esc** clear the keyboard highlight (ignored while a field has focus).

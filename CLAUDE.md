# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server (also serves the DuckDuckGo proxy, see below)
- `npm run build` — `tsc -b && vite build` (type-check then bundle to `dist/`)
- `npm run lint` — ESLint
- `npm run preview` — serve the built bundle

- `npm test` — Vitest (`vitest run`); covers the wander grid, pathfinding, desk slots, chair reach, jam detection and give-up decisions (`interaction/npc/*.test.ts`) and the player session. Pure logic only: nothing that needs Phaser's runtime is tested.

## Architecture

A client-only React 19 + TypeScript + Vite app (SCSS styles, `HashRouter`) deployed to GitHub Pages via `.github/workflows/deploy.yml` on push to `main`. `vite.config.ts` sets `base: '/susan-and-gloria/'`.

There is no backend: the LLM calls run **in the browser** against a local Ollama server.

### Agent pipeline (`src/agents/`)
- `agentGraph.ts` — LangGraph `StateGraph`: `START → orchestrator → (conditional on state.targetAgent) → susan | gloria → END`. Exports the compiled `appGraph`. Shared state includes `onToken` / `onRoute` callbacks that the UI passes in via `appGraph.invoke({...})` (see `pages/Home.tsx`) to stream tokens and learn which persona was routed to.
- `theGreatOne.ts` — the orchestrator node. It asks the LLM to reply with a single word and routes to `gloria` if the output contains "gloria", otherwise defaults to `susan`. Routing options are built from `PERSONAS[*].whyMe`.
- `agents.ts` — `createAgentNode(persona)` factory: builds messages as `GUARDRAIL` + persona system prompt + history + user input, streams the response, and calls `state.onToken`. Returns updated `messages` history (note the reducer replaces the array rather than appending).
- `personas.ts` — `GUARDRAIL` (safety rules that override personas) and `PERSONAS` (system prompt + `whyMe` per persona). Adding a persona requires updating the `createAgentNode` type union, the graph nodes/edges, and the orchestrator's fallback parsing in `theGreatOne.ts`, which hardcodes `gloria`/`susan`.
- `llm.ts` — `createLLM()` is the single place for LLM config (`ChatOpenAI` pointed at `http://localhost:11434/v1`, model `llama3.1:8b`, key `"ollama"`). Ollama must be running locally for chat to work.

### Tools (`src/tools/webSearch.ts`)
LangChain `web_search` tool that fetches `/api/duckduckgo/html/?q=...` and parses results with `DOMParser`. That path only exists via the **Vite dev-server proxy** (`server.proxy` in `vite.config.ts`) — it will not work in the deployed GitHub Pages build.

### The Office (`src/pages/TheOffice.tsx`, `src/game/office/`)
A Phaser 4 mini-game mounted at `/office` (outside `MainLayout`). React owns the page and the chat `<input>`; Phaser owns the canvas. They talk only through `OfficeGame`'s imperative API (`setTyping`, `showPlayerSpeech`, `destroy`), called via a ref; the input's focus/blur toggles `setTyping` so movement keys are disabled while typing. Susan and Gloria are animated four-direction sprites (idle + walk sheets in `public/assets/sprites/<name>/`, generated by `pixel-art/<name>-idle/build.py`) but are not yet wired to the agent graph.

- `OfficeGame.ts` — `Phaser.Game` config (600x400, arcade physics, pixel art) and the API above.
- `OfficeScene.ts` — the scene: `create()` lays the floor, places furniture/NPCs/player, `update()` handles movement. **Edit this to change the room layout** (`place(name, x, y, { solid, flat })`).
- `interaction/player/PlayerWork.ts` + `playerSprite.ts` — standing still in a work zone makes the player sit and type: `OfficeScene.updatePlayerAnim` plays `player-type-<facing>` and seats the player via `NpcSeats`: the same routed chair trip as the coworkers (below), started automatically when they stand still in a zone and cancelled by any movement key, typing or chat; none in reach means they work standing on the idle frame. A jammed chair makes them say a `JAM_PHRASES` line, walk back to the spot and work standing; losing the trip (chair taken by a Shift-pull, blocked, too slow, no way back) makes them say a `FORGETFUL_PHRASES` line and get control back with no work. The session logic is the pure `playerSession.ts`; the work timer starts once they are seated using the chair sandwich (`SeatLayers`: `ChairSheet.png` one depth step behind, `ChairHandleSheet.png` armrests one step in front; per-facing nudge in `CHAIR_OFFSET`). The seated sheet `public/assets/sprites/player/Type.png` is **generated, not hand-edited**: run `python pixel-art/player-type/build.py` (Pillow; also writes `preview.png`). It builds from `Idle.png` (head, legs) and `Shoot.png` (arms). Tunables are constants at the top (`SIT_DROP`, `ARM_X`, `FAR_X`). Side views draw both hands in `side_upper`; the left view is built mirrored, so check both after changing hand positions.
- Susan and Gloria have the same kind of seated sheet (`public/assets/sprites/<name>/Type.png`), also **generated**: run `python pixel-art/npc-type/build.py` (writes both, plus `<name>-preview.png`). It derives from each `Idle.png` and copies the player's look: arms tucked into the torso, belly hands in front/back, a reaching near arm plus a shaded far hand in the side views. Per-character tuning (sleeve colour, `leg_row`, `arm_rows`, `hand_y`) lives in `CHARACTERS`. `CharacterSprite.type` in `playerSprite.ts` loads and animates the sheet, and `OfficeScene.updateSheetAnim` plays it while a coworker is working. If a loose chair (`furniture/Chairs.ts`) is within 5 tiles when they reach a work spot, `interaction/npc/NpcSeats.ts` has them walk to it, pull it back, slide it under them and work seated in the same `SeatLayers`; with no chair in reach they work standing as before.
- `interaction/Shadows.ts` � shadows are **separate images**, not baked into the character sheets (rows 30-31 of every cell are empty). `Shadow.png` (characters) and `ObjectShadow.png` (chairs, 5px flat oval) are generated by `python pixel-art/shadow/build.py`. A `Shadows` instance follows each sprite just behind it in depth; a seated character's own shadow is hidden (`hideWhen`) and `SeatLayers` draws the chair's instead. Nudge the chair shadow with `CHAIR_SHADOW_OFFSET_Y`. The characters' collision body is lifted `FEET_LIFT` px (`constants.ts`) so it ends at the soles, not the shadow rows.
- Pushables (`interaction/pushChain.ts`, pure and tested; wired in `furniture/Chairs.ts` `gate()`, called last in `OfficeScene.update`): chairs and free coworkers are pushed by *drivers*, bodies moving under their own power (the player walking or pulling, a walking coworker). Each frame the resolver decides per axis whether a chain may move; if anything in it would end in a wall, desk, world edge, the player or an immovable coworker, the whole chain stops, the driver included. A coasting chair never pushes a coworker; a chair the player pushes or pulls does; a coworker never pushes a coworker through a chair. Shift pulls the nearest loose chair or free coworker, one at a time; a pulled body trails the player and is let go of (not the player stopped) when blocked. A coworker is immovable while a bubble is up or from reaching its desk (`OfficeScene.isImmovable`). Hosts (`Wander`, `WorkInteraction`, `NpcSeats`) read one signal through `PathFollower.isBlocked`: `PUSH_STOPPED` (push refused) or `PUSH_SHOVED` (first frame displaced, or let go after a pull), set as data on the coworker; a held coworker has `PUSH_HELD` and `Wander` leaves its steering alone. **Tune the feel in `pushTuning.ts`**: chair/coworker mass, chair and shoved-coworker drag, `ROLL_MS`, chair max speed, each coworker's max speed (their walking speed is that times `COWORKER_WALK_FRACTION`), player walk speed, and pull and push speed per chair or coworker (each separate for chairs and coworkers), each commented.
- `interaction/npc/NpcBubbles.ts` — NPC speech bubbles (notice, mutter, scrollable streamed reply); `OfficeScene` delegates its public NPC API to it.
- Work trips (`interaction/npc/WorkInteraction.ts`, `NpcSeats.ts`): a coworker (and the player, see above) claims a free desk in `WorkSlots` (one holder per desk, claimed at the pick; the player holds one while working but is never blocked), walks to its zone along the A* route (`PathFollower`), is turned away with a `DESK_TAKEN_PHRASES` line if the player is in the way, then fetches a chair: a loose chair is in reach if it is within 5 tiles in a straight line and its walking route is at most 15 tiles (`chairReach.ts`, pure). They walk to it (planned on the walker grid), drag it to half a tile behind the work spot (planned on a second, "clearance" grid: `WalkGrid` with the `CHAIR_CLEARANCE_CELLS` footprint, so the 28x16 px chair fits; a chair with no clearance route is skipped) and sit. While towing, `chairJam.ts` watches how far the chair trails the walker: over `JAM_MARGIN_PX` for `JAM_TIME_MS` is a jam, the chair is left (not taken again for `JAMMED_CHAIR_COOLDOWN_MS`, wherever it is moved) and the walker says a `JAM_PHRASES` line and works standing. A trip lost any other way (`giveUp.ts` decides; desk-taken comes first) makes a coworker say a `FORGETFUL_PHRASES` line, release the desk and wander. **Tune the jam and clearance values in `chairTuning.ts`.** Phrase lists live in `interaction/workPhrases.ts`.
- Debug aids (all off by default, ignored while typing in the chat): **G** tints the walk grid (`WalkGridOverlay`); **H** shows the clearance grid (green: a chair fits, yellow: only a walker, red: blocked); **C** shows chair reach (`ChairReachOverlay`: yellow marks the desk each coworker is heading for; the 5-tile range circle per work spot, green lines with the route length for chairs in reach, red with the reason for those filtered out: claimed, recently jammed, too far, no route, route too long, no drag route). In the chat box, `/gloria-work` and `/susan-work` send that coworker to a free desk now. **B** makes the player's current or next chair trip fail as if blocked, to see the give-up.
- `interaction/npc/Wander.ts` — NPC random walk; `interaction/player/Chat.ts` — in-game chat input and the player's speech bubble.
- `map/loadOfficeMap.ts` — loads the Tiled map, floor bounds, and per-tile opaque collision rects.
- `constants.ts` — canvas size, sprite scale, depth layers, feet-collision height.
- `atlases/officeAtlas.ts` — frame rectangles for characters/desks in `PixelOfficeAssets.png`.
- `atlases/interiorAtlas.ts` — frame rectangles for floors/rugs/furniture in `InteriorTilesLITE.png` (labelled map: `docs/interior-atlas-preview.png`).
- Spritesheets are in `public/assets/office/` (credits in `CREDITS.md`); frames are cut from the sheets at runtime. Rendering uses y-based depth sorting (`sortByBottom`) so characters walk behind/in front of objects.
